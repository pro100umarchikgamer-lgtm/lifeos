# Импорт и синхронизация в ULADIM Web

## Как перенести данные

1. Выберите пространство в верхней панели. Откройте **Профиль → Импорт и синхронизация**. На телефоне профиль находится в меню **Ещё**.
2. Выберите заметки, задачи или календарь, затем откройте системный выбор файлов. Можно выбрать несколько файлов за один раз. Для обработки доступны до 50 файлов общим размером до 5 МБ и до 250 записей.
3. Просмотрите найденные записи и предупреждения. Снимите отметки с записей, которые не хотите переносить. Уже существующие записи, конфликты и неподдерживаемые элементы видны в списке.
4. Нажмите **Импортировать**. Сверьте число сохранённых записей, затем откройте соответствующий раздел. Войдите в тот же аккаунт и выберите то же пространство на другом веб-клиенте, чтобы увидеть результат.

Приложение читает файлы в браузере. Сервер получает только записи, которые вы подтвердили. Импортированные записи создаются с видимостью **Личные** в выбранном пространстве. Исходные файлы и записи в прежних приложениях сохраняются.

## Что выбрать в исходном приложении

| Источник | Файл | Что появится в ULADIM |
| --- | --- | --- |
| Заметки в текстовом файле или Apple Notes | TXT или экспорт Markdown (.md), если доступен в вашей версии Apple Notes | Редактируемый текст с заголовками и списками в исходном текстовом представлении. |
| Google Keep | JSON отдельной заметки или ZIP из Google Takeout с файлами Keep | Заголовок, текст и состояния пунктов списка в текстовом виде. Метки, закрепление, архивное состояние, даты и вложения не переносятся. Заметки из корзины пропускаются. |
| Календарь | ICS | Название, дата и время начала, событие на весь день, поддерживаемый часовой пояс и простое повторение. Конец события, описание и место не переносятся. Сложные серии пропускаются с объяснением. |
| Задачи и заметки из совместимого экспорта | JSON версии 1 по примеру ниже | Текст заметки либо название и статус выполнения задачи. Сроки, подзадачи и другие поля задачи пока не переносятся. |

HTML, PDF заметок, восстановление полной резервной копии ULADIM и экспорт Structured пока недоступны. Банковские выписки загружаются отдельно в разделе **Финансы**.

- [Экспорт заметки из Apple Notes](https://support.apple.com/guide/ipad/export-or-print-notes-ipad0f02933b/ipados)
- [Скачивание данных Google Keep](https://support.google.com/keep/answer/10017039?hl=ru)
- [Экспорт Google Calendar](https://support.google.com/calendar/answer/37111?hl=ru)

## Если возник вопрос

- **Файл не распознан.** Сверьте формат с таблицей и попробуйте повторно экспортировать данные. Для текстовых файлов используется UTF-8. Скан, скриншот и PDF заметки пока не подходят.
- **Запись уже есть и отличается.** Импорт сохраняет существующую версию. Проверьте запись в соответствующем разделе, прежде чем вносить изменения вручную.
- **Соединение прервалось при сохранении.** Повторите отправку в открытом окне. Если окно закрыто, снова выберите файл и проверьте предпросмотр. Уже принятые записи будут учтены.
- **Поменялся внешний календарь.** Загрузка ICS переносит снимок событий. Новые изменения во внешнем календаре автоматически не поступают. Google Calendar показан как функция в разработке.

В веб-интерфейсе этот маршрут описан в [руководстве](/docs#import) и [FAQ](/faq#import).

## Контракт совместимого JSON

```json
{
  "format": "uladim-import",
  "version": 1,
  "records": [
    { "kind": "note", "id": "note-17", "body": "# Поездка\n- Проверить билеты" },
    { "kind": "task", "id": "task-42", "title": "Собрать документы", "completed": true }
  ]
}
```

Идентификатор `id` необязателен. Если система-источник его передаёт, используйте стабильный ID записи длиной до 500 символов. Повторный импорт с тем же ID и другим содержимым покажет конфликт. Без ID для распознавания повторов используются поля, которые сохраняет ULADIM. У событий ICS используется `UID`. Ключи ограничены аккаунтом, пространством и типом записи.

Приложение отправляет подтверждённые записи пакетами через существующий API синхронизации. При неопределённом результате повторная отправка сохраняет UUID операций, а ревизия создания защищает существующие записи от перезаписи. Счётчик сохранения опирается на ответы API. Для повторяемой проверки импорта, хранения, двух веб-сеансов и справки используется `python -m tool.check_web_personal_import`.
