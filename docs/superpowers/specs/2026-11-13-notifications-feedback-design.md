# Notification history and recorded usability feedback

The owner requests a complete review of five new Drive recordings, practical interface fixes, execution of the previously deferred release audit, and administrator announcements with three in-app formats. Existing data, authentication, synchronization and financial calculations remain authoritative. No paid service is introduced.

Use the existing Web/Flutter application and staff Control. A persistent, account-isolated inbox supplies both clients. The bell opens a readable page; a message can be read, dismissed, and retained in history. Announcements have draft, preview, publish and cancel states with existing staff MFA, capabilities and audit. Presentation is inbox, compact banner, or dismissible full-screen startup page. Do not interrupt an editor or show an expired/dismissed message again. No real campaign is sent as part of acceptance.

New persistence and endpoints are limited to this explicitly requested notification feature. They do not replace the working push provider, authentication or record APIs. Native reminders also retain private offline history. Read and presentation state must not cross accounts; sign-out removes visible account history immediately.

Review the new videos in their actual screen continuity order, with complete local speech transcription and timestamped frame coverage. Implement demonstrated interaction problems; preserve scenarios the owner's later commentary confirms work. Known early findings: task editor duplication and technical secondary action, inactive income/expense category drill-down, long ledger scrolling, dated calendar/notes presentation. Further confirmed findings enter the implementation ledger before editing.

The audit covers actual current source, release artifacts, live public endpoints, isolated synthetic flows, and official store requirements. Report verified, blocked and unknown separately. No store approval, real purchase, owner enrollment, device notification delivery, or production restore is claimed without evidence. Owner access must preserve MFA and existing enrollment.

## Approach

Extend current components and persist server-owned notification state. A browser-only local list would lose cross-device history; a new external messaging service would add cost and duplicate working infrastructure. The existing service and local SQLCipher storage cover the request with fewer moving parts.

## Acceptance

- Bell and readable history on Web and Android, with clear loading, empty, offline and error states.
- Three announcement previews and a concrete audience/expiry confirmation in Control; access remains role checked.
- Startup display once per account message, outside active editing; expired messages remain history only.
- Recorded financial drill-down and simplified editors work with real synthetic data, narrow screens and larger text.
- Current release audit produces evidence, a prioritized backlog and separate free-store/payment/promotion decisions.
- Publication uses reviewed release guards and rollback. Local implementation is never described as published.
