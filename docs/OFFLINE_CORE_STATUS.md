Новые пути: **Финансы → финансовая основа → счета/категории/переводы/бюджеты/планы/пакеты импорта**; там же накопления/обязательства/инвестиции и импорт. **Модули → проекты/привычки/обучение/списки/активность**, настройка Today. В карточке заметки — теги, связи и чек-листы. В профиле — локальные профили, будущие роли и разрешения.

Все операции поступают через typed ActionEngine. Деньги — integer minor units/BigInt, количество инвестиций — integer micros; диаграммы не являются учётными значениями. Переводы, earmarks, бюджеты и планы не включаются в фактические доходы/расходы. При изменении суммы распределённой операции используйте «Счёт и распределения»: сумма и части сохраняются атомарно. Связанные денежные записи нельзя изменить/удалить в противоречие сохранённому обязательству — сначала исправьте явную связь.

## Производительность

Устранены подтверждённые по коду причины лишней работы: изменения метаданных не перечитывают все записи и не запускают reconciliation напоминаний; refresh ограничен затронутыми таблицами. Бюджет больше не сканирует все записи для каждого исторического периода — используются корзины и пропуск пустых периодов. FIFO не сдвигает массив при каждом закрытии позиции. Текстовый импорт вынесен в isolate; XLSX/XML разбираются в native worker с лимитом времени/распаковки. Списки создают строки лениво; личные модули показывают по 50 строк с продолжением.

**Замеров frames/FPS/переходов на физическом Android нет.** Основной набор records по-прежнему загружается для корректной аналитики; это не настоящая пагинация базы. Профиль 1k/10k записей и при необходимости SQL-агрегация/постраничная загрузка — обязательная проверка перед объявлением производительности принятой.

## Незавершённое

1. **Приоритетный XLS (BIFF/OLE) отсутствует**: безопасный адаптер и fixtures нужны отдельно. XLS/PDF пока отклоняются; предлагается CSV. Поэтому полный пакет C и весь Offline Core не объявляются завершёнными. Поддержка произвольных PDF/OCR не обещается.
2. Нет SDK/Android устройства и канала записи GitHub в этой среде. Dart/Kotlin могут содержать ошибки, выявляемые только компиляцией/запуском. Следующий шаг — публикация патча в рабочей среде и обязательный полный CI; ошибки не маскировать и проверки не отключать.
3. Физическая доставка alarms, OEM/DND/reboot/timezone, фактические layout и profile-производительность остаются открытыми. Чек-лист: `OFFLINE_CORE_ANDROID_CHECKLIST.md`.

Исходные выписки не пишутся в БД/backup/файлы приложения и не передаются на сервер. Сохраняются только подтверждённые нормализованные операции и ключи происхождения. Выбранный исходный файл остаётся у пользователя/SAF-провайдера; LifeOS не удаляет его.
