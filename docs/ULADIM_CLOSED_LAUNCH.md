# ULADIM 3.1: закрытый запуск

Этот документ сопровождает исходники. Он не подтверждает развёртывание VPS,
выдачу TLS, доставку SMTP, полный CI или выпуск новой APK.

## Совместимость

Ветка `feature/uladim-brand` продолжает проверенный
`bb42b6f3a40b7c50ed19916e1d065888b932fc1c`. `main` не изменяется.
Название интерфейса и Android launcher — ULADIM. Сохраняются
`app.lifeos.lifeos`, сертификат из `ANDROID_TEST_CERT.sha256`, SQLCipher,
имена файлов/ключей, UUID, миграции и формат `.lifeosbackup`, включая AAD.
Существующие профили, названия которых задавались пользователем, не переименовываются.
Все 16 пакетов обновлены до версии 11; приложение по-прежнему работает локально.
Модуля хранения документов нет. Банковские файлы остаются на устройстве.

## Доступ владельца до изменений SSH

1. В доверенной консоли VPSPay проверить сервер `violent_coffee`, `vm-13272`,
   IP `144.31.148.122`; вывести только публичный отпечаток:
   `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`.
2. Сравнить отпечаток до первого подключения SSH. Не отключать проверку host key.
3. Установить публичный SSH-ключ владельца; приватный ключ остаётся у владельца.
   Проверить второе независимое подключение с sudo, сохраняя консоль открытой.
4. Сменить раскрытый root-пароль в консоли владельца, не пересылая его в чат.
   Только после проверки ключа отключать парольный SSH и ограничивать root-вход.
   Проверять `sshd -t` до reload. Не закрывать аварийный доступ провайдера.
5. Обновить Ubuntu и установить Docker Engine/Compose из официального apt-репозитория.
   Firewall должен сохранять рабочий SSH и разрешать HTTP/HTTPS. PostgreSQL
   не публикует порт. Не менять DNS nameservers и не создавать новую VPS.

## Конфигурация существующего backend

Использовать `/opt/uladim` для рабочей копии. `.env` создаётся из `.env.example`
в режиме 600 и никогда не коммитится. Задать:

- `LIFEOS_DOMAIN=api.getuladim.space`, реальный контакт `ACME_EMAIL`;
- независимые случайные URL-safe пароли app/admin PostgreSQL, Fernet mail key,
  rate-limit key; сохранить их в защищённом хранилище владельца;
- реальный SMTP provider, порт/TLS, логин и пароль через защищённый редактор;
  `EMAIL_FROM=ULADIM <...>` с подтверждённого домена отправителя;
- `REGISTRATION_MODE=closed`, `REGISTRATION_ALLOWLIST` — точные email участников
  через запятую, без wildcard. Пустой список запрещает все новые регистрации.
  Список проверяет API до создания аккаунта/почтовой задачи. Удаление адреса
  из списка не удаляет существующий аккаунт и не ломает recovery/sync.

`docker compose up -d --build` запускает PostgreSQL 17, checksummed migrations,
API, mail worker и Caddy. Постоянные volumes не пересоздавать и не удалять.
`docker compose config` без `--quiet` может раскрыть секреты: не включать его
вывод в отчёты. Обычная смена `.env` не меняет пароль уже созданной роли БД.

Снаружи проверить DNS A, валидную цепочку TLS и
`https://api.getuladim.space/health/ready`. Не использовать `curl -k`.
Проверить отсутствие публичного `/metrics` и порта 5432. Реально получить
письмо в ящике каждого тестера; успешная постановка в очередь не равна доставке.

## Резервирование и наблюдение

До запуска таймеров создать `/etc/uladim/backup.key` с не менее 32 случайными
байтами (каталог 700, файл 600), сохранить независимую копию у владельца.
Ключ и `.env` не лежат в репозитории/публичных артефактах. Выполнить первую
резервную копию `scripts/backup.sh /etc/uladim/backup.key /var/backups/uladim`.
Проверить checksum и `scripts/restore.sh BACKUP KEY uladim_restore_YYYYMMDD`
в НОВУЮ БД; сравнить пользователей, UUID, суммы и sync cursors. Уже существующая
БД отклоняется. Боевой target не переключается автоматически.

После проверки скопировать четыре unit-файла из `deploy/systemd` в
`/etc/systemd/system`, выполнить `systemctl daemon-reload` и включить
`uladim-backup.timer`, `uladim-monitor.timer`. Проверить `systemctl list-timers`
и журналы обоих services. Монитор проверяет API/БД, mail heartbeat, свободное
место и свежесть завершённого зашифрованного backup. Таймеры не отправляют
внешние оповещения: независимый получатель аварийных уведомлений настраивается
отдельно. Ничего автоматически не удаляется; Google Drive не используется.
Prometheus остаётся опциональным и доступным только через localhost/SSH.

## Финальная проверка и единственная APK

После публикации ветки автоматический push выполняет focused CI без APK.
Исправить конкретные сбои, проверить полученные скриншоты. Затем вручную
запустить `stage1.yml` на `feature/uladim-brand` с `focused=false`,
`force_full_validation=true`, `build_apk=true`. Сборка передаёт
`LIFEOS_API_ORIGIN=https://api.getuladim.space`, проверяет applicationId,
название ULADIM, прежний сертификат и `versionCode > 83001`.
Секрет существующего keystore не переносить в файлы или чат.

Обязательно проверить установку этой APK поверх LifeOS 83001 без uninstall
и очистки данных. Сохранить личную контрольную запись, UUID/сумму и настройки;
после обновления проверить их наличие. Провести регистрацию/верификацию,
recovery с отзывом старой сессии, две реальные HTTPS-сессии родителей,
приватные записи, shared update, отключение сети/перезапуск, replay,
конфликт и отзыв прав ребёнка. Локальный HTTP-тест не заменяет эту проверку.
APK предоставляется только участникам закрытого теста после всех gate.
