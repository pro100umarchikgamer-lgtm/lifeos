# Утверждённая последовательность v0.1

## Текущая работа: Offline Core Expansion

Основа — GitHub main `23e537d7256bbedf37d24a2d4219ef3f6019f996`, мастер-спецификация и `OFFLINE_CORE_EXECUTION_BRIEF.md`. Прежний порядок заменён утверждённым приоритетом автономной личной работы. Полный продуктовый объём v0.1 сохранён.

1. Personal Core и утверждённый Home: существующие CRUD, encrypted SQLCipher, общий ActionEngine, календарь/Android alarms, резервные копии, темы и RU/EN сохраняются.
2. A: точные счета, категории, переводы, распределения, бюджеты/перенос, ручное подтверждение финансовых планов.
3. B: виртуальные/связанные накопления, обязательства и ручные инвестиции.
4. C: временный локальный импорт, сопоставление, дубли, подтверждение, обратимые пакеты. XLS остаётся открытым; банковские API и хранение документов исключены.
5. D: связанные проекты/задачи, привычки/календарь, обучение, заметки/списки, домашние шаблоны, минимальная активность/сон, настраиваемый Today.
6. E/F: локальные неизменяемые профили/структуры прав, Android UX, восстановление всей схемы, регрессии, реальные устройства и профиль производительности. Исходники кандидата подготовлены; приёмка и APK пока не подтверждены.
7. После принятия Offline Core — отдельная работа над реальной авторизацией, заменяемым backend (Supabase — кандидат), пакетной синхронизацией и проверяемыми семейными правами. Два равных родителя, детские бюджеты/запросы денег и совместные записи остаются обязательным будущим объёмом v0.1. Локальные профили не являются семейным доступом.
8. Завершение v0.1: 15 языков / 16 локалей, включая узбекские Latin/Cyrillic, полноценные переводы, безопасность, восстановление, доступность, Android телефон/планшет, iOS-ready адаптеры. Все сценарии мастер-спецификации должны пройти.

v0.2 AI, внешняя бета и v1.0 остаются последующими версиями, не реализуются этим заданием. Сервер, AI, документы и банковская автоматизация не добавлены. Текущий статус и непроверенные проверки: `OFFLINE_CORE_STATUS.md`.

## Будущее требование: обновление Android внутри приложения

На этапе подготовки выпуска предусмотреть понятный экран проверки и установки обновления с двумя **раздельными каналами распространения**:

- Для установок из Google Play применять разрешённые магазином механизмы обновления внутри приложения (гибкий или немедленный сценарий по ситуации), без самостоятельной подмены APK.
- Для независимо распространяемых подписанных APK показывать версию и изменения, получать пакет только из доверенного источника, проверять целостность и совместимость подписи и передавать установку системному установщику после явного действия пользователя. Не выполнять тихую установку и не смешивать каналы, если подписи несовместимы.

Сейчас это только требование к будущему UX и выпуску: загрузка обновлений, сервер метаданных и установка APK не реализуются в текущем Offline Core.
