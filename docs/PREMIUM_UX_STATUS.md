# Premium UX: состояние реализации

База GitHub: `7eccad1261943413abd8a621cb7f30a49097a2fa`, main.
Локальная старая история сохранена в ветке `preserved/local-before-premium`.
Снимок актуального main перенесён через GitHub API, включая исправления Flutter
и постоянный тестовый сертификат. История GitHub не переписывалась.

## Изменения в исходниках

- `domain/appearance.dart`, `ui/design.dart`, `ui/appearance_editor.dart`:
  единый версионированный JSON оформления, атомарное Apply, отменяемый живой
  предпросмотр, Reset с последующим Apply, system/light/dark, Emerald/Soft
  Pistachio/Sky/Warm Sand, три формы и три вида поверхностей. Цветовые роли
  генерируются Material 3; семантические цвета расходов и доходов сохраняются.
- Android 12+: акцент обоев через небольшой native bridge; отдельная палитра
  используется при отсутствии поддержки. При возвращении в приложение цвета
  обоев обновляются, если опция включена.
- `ui/entry_sheet.dart`, `quick_add.dart`, `calendar.dart`: крупные основные поля,
  общая закреплённая кнопка сохранения, прокрутка полей над клавиатурой,
  Today/Tomorrow/Next Week/No Date, раскрываемые повторения и режим напоминания.
  Полноэкранный редактор заметок сохраняет текст при ошибке записи и CAS-проверки.
- Платежи: быстрые варианты **назначения** заполняют прежнее поле label.
  Это не новая таксономия категорий; произвольное описание остаётся доступным.
- Финансы: крупные суммы отдельно от компактного утверждённого Home; выбор
  месяца/диапазона с прошлым месяцем, последними 30 днями и подсказками выбора
  начала/конца. Введённый ранее диапазон открывается в правильном режиме.
- Календарь: различимые задачи/заметки/события, читаемые названия и состояния.
- Настройки: оформление, язык/регион, календарь/время, уведомления и данные.
  Разрешения/диагностика открываются отдельно; тест уведомления доступен сразу.
- Backup: отдельный пошаговый экран с состояниями пароля, шифрования, выбора
  файла, проверки и подтверждения. Запрет ухода во время операции. Прежние
  требования пароля, аутентифицированное шифрование, проверка записанного файла,
  атомарный restore и контроль целостности не ослаблены. Новое оформление
  проверяется при restore; схема SQLCipher остаётся v3, миграции не менялись.

## Краткая сверка UX до изменений

Использованы принципы, а не копирование экранов:

- [Material 3](https://m3.material.io/styles/color/the-color-system): тональные
  роли, читаемость поверхностей; [motion](https://m3.material.io/styles/motion).
- [Todoist Quick Add](https://www.todoist.com/help/todoist/features/use-task-quick-add-in-todoist-va4Lhpzz),
  [Apple Reminders](https://support.apple.com/en-us/102484): сначала быстрый ввод,
  даты и дополнительные свойства рядом с записью.
- [TickTick Calendar](https://help.ticktick.com/articles/7055782166172532736),
  [Google Calendar](https://support.google.com/calendar/answer/72143): день и
  повестка, выбор времени рядом с событием.
- [Keep](https://support.google.com/keep/answer/2888240): комфортное место для текста.
- [Revolut analytics](https://help.revolut.com/help/accounts/budget-and-analytics/what-is-the-analytics-dashboard/):
  суммы и период должны иметь приоритет над второстепенными деталями.
- [Apple entering data](https://developer.apple.com/design/human-interface-guidelines/entering-data):
  подходящая клавиатура, меньше обязательных действий.

## Производительность: доказанные изменения и ограничения

По прежнему коду одна обычная refresh выполняла два чтения каждого набора
records/calendar/occurrences, даже при пустой очереди native actions. Теперь
в этом случае каждое чтение выполняется один раз. Дополнительное чтение остаётся
после применения native actions, чтобы отображать именно сохранённое состояние.
Изменения оформления/валюты/регионального формата больше не читают базу.

Неизменившийся payload напоминаний не отменяется/устанавливается повторно.
Кэш публикуется только после успешных native reconcile и durable marks;
возвращение приложения, смена разрешений и важных настроек форсируют reconcile.
Действия native не подтверждаются при неизвестной ошибке домена.

MaterialApp слушает отдельные изменения оформления/локализации. Обычные данные
обновляют HomeShell, не создавая повторно темы приложения. Календарь переиспользует
расчёт месяца при выборе дня; состояния индексируются вместо повторных поисков.
Длинные списки имеют отдельные ленивые элементы, а не одну огромную Column.
Модели и список описаний виджетов пока остаются в памяти; пагинация базы не добавлялась.

**Это анализ изменения числа операций, не измеренное ускорение кадров.**
Замеров FPS/p95 и реальных скриншотов этого коммита нет: SDK отсутствует,
GitHub запись заблокирована. Debug FPS не используется как доказательство.

Добавлен безопасный UI benchmark на 1000 фиктивных транзакций, который не открывает
личную базу и отказывается работать вне profile mode:

```sh
flutter drive --profile --driver=test_driver/ux_profile_driver.dart --target=integration_test/ux_profile_test.dart -d DEVICE_ID
```

Результат: `performance/ux-profile.json`. Запускать на физическом Android с
описанием модели, ОС, частоты экрана и версии Flutter; сравнивать одинаковые
прогоны до/после, build/raster frame times и пропущенные кадры. Это UI-нагрузка,
а не проверка скорости SQLCipher или доставки будильников.

## Проверки и финальная доставка

Локально выполняются Python-тесты схемы/миграций/ограничений, защиты сборки
при неправильном ключе, проверка RU/EN-пакетов, shell syntax и diff whitespace.
Проверка парных разделителей Dart вспомогательная, она не заменяет компиляцию.

Добавлены Flutter-тесты round-trip оформления, контраста, fallback, persist/preview,
подсчёта запросов/reconcile, обработки ошибок, клавиатуры и дат. Android integration
проверяет сохранение оформления после reopen, rollback повреждённой настройки
при restore и bridge обоев. Все эти новые Flutter-проверки **ещё не выполнены**.

Workflow содержит обязательные analyze, unit/widget, миграции/SQLCipher на
эмуляторе, Kotlin compile и 23 сценария скриншотов с кириллическим тестовым шрифтом.
Существующие 17 сохранены; добавлены две палитры, оформление, заметка, задача и событие.
Обновление goldens предназначено для визуального ревью, не является автоматическим
доказательством совпадения с `docs/reference/approved-home.jpg`.

После публикации на main запускать **один** workflow_dispatch с
`force_full_validation=true`, `build_apk=true`. Новый исходный код также автоматически
отменяет переиспользование старого validation proof. Финальный APK собирается
`--release` после всех проверок, подписывается тем же защищённым keystore,
проверяется закреплённый сертификат/applicationId/versionCode. Номер увеличивается
по прежнему номеру workflow; локальный pubspec `0.1.1+2` не используется как номер
CI APK. Артефакт: `lifeos-release-test-apk-<commit>` с публичными отчётами подписи.

## Проверка на Android

1. Установка поверх предыдущей версии с тем же сертификатом без удаления данных;
   записи, ID, история, язык и напоминания остаются на месте.
2. Оформление: preview/cancel/apply/restart/reset; Android 12+ обои и fallback.
3. Узкий экран, крупный шрифт, TalkBack, reduced motion, клавиатура: все Save доступны.
4. CRUD и undo четырёх типов, денежные суммы и диапазоны, все календарные повторы.
5. Уведомления/важные/будильники при экране off, перезагрузке, смене зоны и запрете
   разрешений; snooze/dismiss, диагностика и тест уведомления.
6. Backup: отказ выбора файла, неправильный пароль, повреждение файла, подтверждение,
   сохранность прежних данных при неудачном restore.
7. Profile-прогоны прокрутки и навигации. Доставка и плавность на физическом устройстве
   не считаются проверенными до выполнения этих пунктов.
